## 1. กลุ่มผู้ใช้งานจำลอง (User Personas)

### 👤 Persona 1: คุณธนกฤต วงศ์สุวรรณ (นักศึกษา & ผู้ซื้อสินค้าดิจิทัล)
* **บทบาทในระบบ:** ลูกค้าทั่วไป (Customer / Buyer)
* **อายุ:** 21 ปี | **อาชีพ:** นักศึกษาคณะวิศวกรรมศาสตร์
* **พฤติกรรมและความชำนาญทางเทคโนโลยี:** ใช้งานสมาร์ทโฟนและแล็ปท็อปเป็นประจำ ชอบเรียนรู้เทคโนโลยีใหม่ๆ นิยมซื้อ E-Books และ UI Kits เพื่อใช้ในการเรียนและทำโปรเจกต์
* **เป้าหมาย (Goals):**
  - ต้องการค้นหาและซื้อไฟล์แม่แบบ (Templates) และหนังสือเขียนโค้ดที่เข้าใจง่ายในราคาเข้าถึงได้
  - ต้องการจ่ายเงินสะดวกรวดเร็วผ่าน Mobile Banking (PromptPay QR) โดยไม่ต้องผูกบัตรเครดิต
  - ต้องการเข้าถึงไฟล์ที่ซื้อได้ตลอดเวลา สามารถเปิดอ่านออนไลน์ได้ทันทีโดยไม่ต้องดาวน์โหลดโปรแกรมเสริม
* **ปัญหาและอุปสรรคเดิม (Pain Points):**
  - เว็บซื้อขายทั่วไปมักส่งลิงก์ดาวน์โหลดผ่านอีเมลที่ตกไปอยู่ในโฟลเดอร์ Junk/Spam
  - ลิงก์ดาวน์โหลดหมดอายุ หรือไฟล์สูญหายเมื่อเปลี่ยนอุปกรณ์
* **ฟีเจอร์ของ Book Sangdai ที่ตอบโจทย์:**
  - **My Library Digital Vault:** คลังดิจิทัลส่วนตัวที่เก็บไฟล์ที่ซื้อไว้อย่างถาวร
  - **In-Browser Apple PDF Reader:** เปิดอ่านอีบุ๊กได้ทันทีในเบราว์เซอร์ พร้อมหน้าต่าง Responsive รองรับมือถือ
  - **PromptPay QR Code:** สแกนจ่ายง่าย มีเวลานับถอยหลังและแจ้งเตือนสถานะทันที

### 🏪 Persona 2: คุณวรัญญา จิตต์มั่นคง (นักเขียน & ผู้สร้างสรรค์ผลงานอิสระ)
* **บทบาทในระบบ:** ร้านค้าพาร์ทเนอร์ (Merchant / Creator)
* **อายุ:** 28 ปี | **อาชีพ:** Digital Creator & Technical Writer
* **พฤติกรรมและความชำนาญทางเทคโนโลยี:** ผลิตผลงาน E-Books และ Design Assets จำหน่ายเป็นอาชีพเสริม คุ้นเคยกับเครื่องมือออกแบบและอินเทอร์เน็ต
* **เป้าหมาย (Goals):**
  - ต้องการมีหน้าร้านดิจิทัลของตนเองเพื่อจำหน่ายผลงานโดยไม่ต้องตั้งค่าเซิร์ฟเวอร์ที่ซับซ้อน
  - ต้องการรับเงินโอนตรงเข้าบัญชีพร้อมเพย์ของตนเองโดยไม่ถูกหักค่าธรรมเนียมสูงเกินไป
  - ต้องการระบบที่ป้องกันการละเมิดลิขสิทธิ์ไฟล์ผลงานของตนเอง
* **ปัญหาและอุปสรรคเดิม (Pain Points):**
  - กังวลเรื่องการถูกคัดลอกไฟล์มาสเตอร์ (PDF) ไปแจกจ่ายต่อในกลุ่มออนไลน์
  - การจัดการคำสั่งซื้อแบบแชตพูดคุยใช้เวลามาก และมักตรวจสลิปปลอมได้ยาก
* **ฟีเจอร์ของ Book Sangdai ที่ตอบโจทย์:**
  - **Merchant Dashboard:** ระบบจัดการสินค้า สต็อก ราคา และหมวดหมู่ที่ใช้งานง่าย
  - **Slip Verification Workflow:** ตรวจสอบสลิปโอนเงินของลูกค้าก่อนกดยืนยันปล่อยไฟล์
  - **Dynamic PDF Watermarking:** ฝังลายน้ำชื่อ-อีเมลของผู้ซื้อลงบนเอกสาร PDF อัตโนมัติ ป้องกันการแจกจ่ายต่อ
  - **Delete Protection Modal:** ป้องกันการลบสินค้าโดยไม่ตั้งใจด้วยการบังคับพิมพ์รหัสยืนยัน

### 👑 Persona 3: คุณกิตติศักดิ์ เจริญกิจ (ผู้ดูแลระบบแพลตฟอร์ม)
* **บทบาทในระบบ:** ผู้ดูแลระบบส่วนกลาง (Super Admin)
* **อายุ:** 35 ปี | **อาชีพ:** Platform System Administrator
* **เป้าหมาย (Goals):**
  - ตรวจสอบความถูกต้องของร้านค้าและรายการสั่งซื้อทั้งระบบ
  - ดูแลความปลอดภัยของข้อมูลผู้ใช้ และปฏิบัติตามกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA)
  - ติดตามยอดจำหน่ายรวม (Gross Merchandise Value: GMV) และประสิทธิภาพของแต่ละร้านค้า
* **ฟีเจอร์ของ Book Sangdai ที่ตอบโจทย์:**
  - **Admin Console:** ศูนย์ควบคุมส่วนกลางแสดงผลยอดขายแบบ Sparkline ชัดเจน
  - **Store Application Management:** ตรวจสอบและกดอนุมัติ/ปฏิเสธร้านค้าที่สมัครเข้ามา
  - **User & Order Audit:** ค้นหาประวัติธุรกรรม และส่งออกข้อมูลเป็น CSV ได้อย่างปลอดภัย

## 2. โครงสร้างสถาปัตยกรรมข้อมูลและพิมพ์เขียวหน้าจอ (Wireframes & UI Layout)

### 2.1 แผนผังสถาปัตยกรรมสารสนเทศ (Information Architecture)
```text
[Book Sangdai Navigation Bar]
 ├── [Storefront / Catalog] (หน้าแรก / ค้นหา / หมวดหมู่)
 │     ├── Hero Banner (แนะนำผลงานเด่น & แคมเปญ)
 │     ├── Category Capsule Filters (E-Book, Notion, Figma, Code, Assets)
 │     ├── Bento Grid Showcase (การ์ดสินค้าพร้อมป้ายลดราคา)
 │     └── Product Detail Modal (ดูรายละเอียด / เพิ่มลงตะกร้า / ซื้อทันที)
 ├── [Cart Drawer] (แถบตะกร้าสินค้าเลื่อนข้าง)
 │     ├── รายการสินค้าและราคาแต่ละชิ้น
 │     ├── ป้ายสิทธิประโยชน์ (จัดส่งไฟล์ฟรีทันที)
 │     └── ปุ่มชำระเงินด้วย PromptPay QR (Login Gate)
 ├── [Checkout & Payment]
 │     ├── ขั้นตอนที่ 1: ตรวจสอบข้อมูลผู้ซื้อ & บัญชีล็อกอิน
 │     ├── ขั้นตอนที่ 2: สแกน PromptPay QR & นับเวลาถอยหลัง 10 นาที
 │     └── ขั้นตอนที่ 3: แนบสลิปโอนเงิน & รอร้านค้าอนุมัติ
 ├── [My Library] (คลังหนังสือดิจิทัลส่วนตัว)
 │     ├── แท็บ "คลังหนังสือพร้อมอ่าน" (PAID) -> อ่านในเบราว์เซอร์ / ดาวน์โหลดไฟล์
 │     └── แท็บ "รายการรอตรวจสอบสลิป" (PENDING) -> ติดตามสถานะ
 ├── [Merchant Portal] (สำหรับบัญชีร้านค้า)
 │     ├── รายการคำสั่งซื้อ & สลิปที่ต้องตรวจสอบ
 │     ├── จัดการรายการสินค้า (เพิ่ม / แก้ไข / ลบด้วยรหัสยืนยัน)
 │     └── ศูนย์รายงานสถิติยอดขาย (Report Center)
 └── [User Profile & Auth]
       ├── Google OAuth & Email Login / Register
       ├── ข้อตกลงการใช้งานและนโยบายความเป็นส่วนตัว (PDPA 100% Reading Gate)
       └── ยื่นขอเปิดร้านค้า (Merchant Application)
```

## 3. รายงานผลการตรวจการเข้าถึงตามมาตรฐาน WCAG 2.1 AA (Accessibility Audit Report)

ระบบ Book Sangdai ได้รับการตรวจสอบและปรับปรุงให้สอดคล้องกับมาตรฐาน **W3C Web Content Accessibility Guidelines (WCAG 2.1) ระดับ AA** เพื่อให้มั่นใจว่าผู้ใช้งานทุกกลุ่ม รวมถึงผู้พิการทางสายตาหรือการเคลื่อนไหว สามารถเข้าถึงและใช้งานระบบได้อย่างราบรื่น

| หมวดหมู่การตรวจ | กฎเกณฑ์ที่ตรวจสอบ (Criteria) | วิธีการดำเนินงานในระบบ Book Sangdai | ผลการประเมิน |
| :--- | :--- | :--- | :---: |
| **1. การรับรู้ได้ (Perceivable)** | **1.1.1 Non-text Content**<br>(มีคำอธิบายข้อความสำหรับรูปภาพ) | รูปภาพสินค้าทุกชิ้นมี `alt="ชื่อสินค้า"` และระบุขนาดสัดส่วนที่ชัดเจน ป้องกันรูปภาพโหลดช้าหรือไม่แสดงผล | **PASS** |
| | **1.4.3 Contrast (Minimum)**<br>(อัตราส่วนคอนทราสต์ของสี) | ข้อความหลักใช้สี Charcoal `#1d1d1f` บนพื้นหลัง Porcelain `#fbfbfd` ให้ค่า Contrast Ratio **14.2:1** (สูงกว่าเกณฑ์ขั้นต่ำ 4.5:1 มาก) | **PASS** |
| | **1.4.11 Non-text Contrast**<br>(คอนทราสต์ของปุ่มและขอบเส้น) | เส้นขอบของ Input ฟอร์มและปุ่มมีค่าคอนทราสต์มากกว่า 3.0:1 มองเห็นขอบเขตชัดเจน | **PASS** |
| **2. การสั่งการได้ (Operable)** | **2.1.1 Keyboard Navigable**<br>(ควบคุมด้วยคีย์บอร์ดได้ 100%) | ผู้ใช้สามารถใช้ปุ่ม `Tab`, `Shift+Tab`, `Enter`, และ `Space` นำทางและกดปุ่มได้ครบทุกฟังก์ชัน | **PASS** |
| | **2.1.2 No Keyboard Trap**<br>(ไม่มีการติดกับดักคีย์บอร์ด) | ทุก Modal (เช่น Product Modal, Auth Modal, Cart Drawer) สามารถกดปุ่ม `Escape (ESC)` หรือ Tab เพื่อปิดหน้าต่างได้ | **PASS** |
| | **2.4.7 Focus Visible**<br>(เห็นตำแหน่งโฟกัสชัดเจน) | ทุกองค์ประกอบที่รับโฟกัส มีขอบเส้นแสดงตำแหน่ง `focus-visible:ring-2 focus-visible:ring-black` อย่างเด่นชัด | **PASS** |
| | **2.5.5 Target Size**<br>(ขนาดปุ่มสำหรับสัมผัส) | ปุ่มสัมผัสทุกปุ่ม (เช่น ปุ่มปิด, ปุ่มเลือกหมวดหมู่, ปุ่มในตะกร้า) มีขนาดไม่น้อยกว่า **44 x 44 พิกเซล** ตามมาตรฐาน Touch Target | **PASS** |
| **3. ความเข้าใจได้ (Understandable)** | **3.2.1 On Focus / On Input**<br>(พฤติกรรมคาดเดาได้) | เมื่อคลิกฟิลด์ฟอร์ม จะไม่มีการส่งข้อมูลหรือเปลี่ยนหน้าโดยไม่ได้รับการสั่งการจากผู้ใช้ | **PASS** |
| | **3.3.1 Error Identification**<br>(แจ้งข้อผิดพลาดชัดเจน) | ฟอร์มสั่งซื้อและเข้าสู่ระบบมีการแจ้งเตือนด้วยสีแดง พร้อมไอคอนและข้อความอธิบายที่เข้าใจง่าย | **PASS** |
| **4. ความทนทาน (Robust)** | **4.1.2 Name, Role, Value**<br>(ความเข้ากันได้กับ Screen Reader) | ใช้ Semantic HTML (`<header>`, `<nav>`, `<main>`, `<section>`, `<button>`) พร้อมแอตทริบิวต์ `aria-label` บนปุ่มที่มีเฉพาะไอคอน | **PASS** |
