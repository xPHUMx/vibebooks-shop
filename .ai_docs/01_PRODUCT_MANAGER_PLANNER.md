# 📋 01. Product Manager / Planner Agent Document

**Role:** Product Manager  
**Goal:** แปลงไอเดียของเว็บแอปเป็น Product Requirements (PRD), ขอบเขตงาน (Scope), และจัดลำดับความสำคัญของงาน (User Stories)  
**System Prompt:**
> "คุณคือ Product Manager ที่มีประสบการณ์สูง คุณมีหน้าที่รับฟังไอเดียเว็บแอปจากผู้ใช้ แล้ววิเคราะห์ออกมาเป็นฟีเจอร์หลัก (Core Features), ขอบเขตงาน (Scope), และจัดลำดับความสำคัญของงาน (User Stories) ให้ชัดเจน ห้ามเขียนโค้ด ให้เน้นการกำหนดโครงสร้างและเป้าหมายของแอปพลิเคชัน"

## 1. ข้อมูลสังเขปของโปรเจกต์ (Project Overview)
- **ชื่อแบรนด์:** Book Sangdai (บุ๊คสร้างได้ / บุ๊คสั่งได้)
- **วิสัยทัศน์:** Digital Library & E-Book Marketplace แพลตฟอร์มคลังหนังสือดิจิทัลและผลงานคุณภาพระดับมืออาชีพ พร้อมระบบอ่านไฟล์ PDF ในเบราว์เซอร์, การดาวน์โหลดไฟล์มาสเตอร์, และการจัดการคลังอย่างปลอดภัย
- **กลุ่มผู้ใช้งานหลัก:**
  1. **ผู้ซื้อทั่วไป (Buyer / Guest):** ค้นหา, ดูตัวอย่าง, สั่งซื้อผ่าน QR PromptPay, แนบสลิป, ตรวจสอบสถานะการอนุมัติ, อ่านหนังสือในคลัง
  2. **สมาชิกที่ลงทะเบียน (Registered User):** ยืนยันตัวตนผ่าน Gmail OTP หรือ Google OAuth, เก็บสิทธิ์คลังดิจิทัลถาวร, จัดการลบ E-book ออกจากคลัง
  3. **ร้านค้า / ผู้สร้างสรรค์ (Merchant):** ลงผลงาน, ตรวจสอบสลิปและอนุมัติปล่อยไฟล์, จัดการรายการสั่งซื้อ
  4. **ผู้ดูแลระบบ (Admin):** ตรวจสอบภาพรวมทั้งระบบ, จัดการผู้ใช้และร้านค้า

## 3. User Stories & Acceptance Criteria

### User Story 1: การบังคับตรวจสอบอีเมลในฐานข้อมูลก่อนส่ง OTP
- **As a:** ผู้ใช้งานทั่วไป
- **I want to:** ทราบทันทีเมื่อพยายามเข้าสู่ระบบด้วยอีเมลที่ไม่มีในฐานข้อมูล
- **So that:** ไม่สามารถขอ OTP สุ่มสี่สุ่มห้าได้ และต้องผ่านขั้นตอนสมัครสมาชิกและยินยอมข้อตกลงก่อน
- **Acceptance Criteria:**
  1. เมื่อกรอกอีเมลในแท็บ "เข้าสู่ระบบ" และอีเมลนั้นยังไม่มีในฐานข้อมูล: Backend ส่ง Error `ไม่มีเมลนี้ในระบบ กรุณาสมัครสมาชิกก่อน`
  2. UI แสดงข้อความสีแดงเตือนชัดเจน พร้อมปุ่มลัด `👉 กดที่นี่เพื่อสมัครสมาชิก`
  3. ไม่มีการส่ง OTP ออกไปยังอีเมลที่ไม่มีในระบบเด็ดขาด

### User Story 2: การอ่านข้อตกลงในการสมัครสมาชิก และ Gmail Login ใหม่ (Consent Reading Gate)
- **As a:** ผู้ใช้งานใหม่ที่กำลังสมัครสมาชิก หรือผู้ใช้ที่เข้าสู่ระบบผ่าน Gmail (Google OAuth) เข้ามาครั้งแรก
- **I want to:** เลื่อนอ่านข้อตกลงและนโยบายความเป็นส่วนตัว (EULA & PDPA) ทั้ง 2 ส่วนจนครบ 100% และกดยืนยันยินยอม
- **So that:** ผู้ใช้รับทราบสิทธิ์และเงื่อนไขการใช้งานอย่างถูกต้องตามกฎหมาย PDPA และระบบบันทึก Audit Trail สู่ฐานข้อมูลจริง

### User Story 3: การลบ E-book ออกจากคลังด้วยรหัส Catalog สีแดง
- **As a:** ผู้ใช้งานที่มี E-book ในคลัง
- **I want to:** ลบ E-book ออกจากคลังได้โดยต้องยืนยันรหัส Catalog
- **So that:** ป้องกันการกดลบโดยไม่ได้ตั้งใจ (Accidental Deletion)

### User Story 4: ศูนย์รายงาน & สถิติร้านค้า (Merchant Report Center)
- **As a:** พ่อค้า / เจ้าของร้านค้า
- **I want to:** ดูสรุปรายได้รวม ยอดขายตามช่วงเวลา สินค้าขายดี และประวัติคำสั่งซื้อ พร้อมปุ่มส่งออกรายงาน CSV และพิมพ์รายงาน
- **So that:** สามารถวิเคราะห์ยอดจำหน่ายและวางแผนการตลาดได้อย่างแม่นยำ

### User Story 5: ศูนย์รายงานระบบกลาง (Admin Report Center & Audit Trail)
- **As a:** ผู้ดูแลระบบ (Admin)
- **I want to:** ดูภาพรวม Platform GMV, สถิติเปรียบเทียบผลงานของทุกร้านค้า (Store Performance Matrix), และส่งออก Master CSV
- **So that:** กำกับดูแลระบบและตรวจสอบความโปร่งใสของธุรกรรมได้อย่างครบถ้วน

### User Story 6: การอัปโหลดรูปภาพร้านค้าและแสดงผลทันที (Instant Store Logo)
- **As a:** พ่อค้าและผู้ใช้งานที่ตั้งค่าร้านค้า
- **I want to:** เห็นภาพโลโก้ร้านค้าทันทีที่เลือกไฟล์ และระบบบันทึกลงฐานข้อมูลให้อัตโนมัติโดยไม่ต้องกังวลว่าจะลืมกดบันทึก
- **So that:** รูปภาพร้านค้าแสดงผลขึ้นทันที ไม่ค้าง ไม่หาย และมี Fallback สวยงาม

### User Story 7: การเน้นย้ำห้ามปิดหน้าระหว่างสแกน QR Code (Checkout Anti-Drop Gate)
- **As a:** ลูกค้าที่กำลังสแกนจ่ายเงินผ่าน QR Code
- **I want to:** ได้รับคำเตือนอย่างเด่นชัดที่สุดว่าห้ามปิดหน้านี้เด็ดขาดจนกว่าจะแนบสลิป
- **So that:** ไม่ปิดแท็บไปก่อนที่ระบบจะตรวจรับสลิปและส่งมอบไฟล์ E-Book เข้าคลังดิจิทัล

### User Story 8: การแสดงไอคอนประจำหมวดหมู่สินค้าในหน้าหลัก (Category Icons)
- **As a:** ผู้เข้าชมและลูกค้าหน้าร้าน
- **I want to:** เห็นไอคอนที่บ่งบอกประเภทของหมวดหมู่แต่ละอย่างบนปุ่มตัวกรอง (Category Pills) อย่างเด่นชัด
- **So that:** สามารถแยกแยะและเลือกดูหมวดหมู่ที่ต้องการได้อย่างรวดเร็วและน่าใช้งาน (เช่น อีบุ๊ค, ดีไซน์ Figma, โค้ด, โมเดล 3D, AI)

### User Story 9: การแสดงเปอร์เซ็นต์ส่วนลดบนการ์ดสินค้า (Discount Percentage Badges)
- **As a:** ลูกค้าที่กำลังเลือกซื้อสินค้า
- **I want to:** เห็นป้ายลดราคาระบุเปอร์เซ็นต์ที่ลดจริงอย่างชัดเจน (เช่น `ลด 51%` หรือ `-51%`) บนการ์ดสินค้าที่มีโปรโมชันลดราคา
- **So that:** ทราบทันทีว่าสินค้าชิ้นนั้นประหยัดได้เท่าไหร่และกระตุ้นการตัดสินใจซื้อได้ดียิ่งขึ้น

### US-CAT-01: การจัดหมวดหมู่ให้ตรงกัน 100% ระหว่างหน้าร้านและฝั่งร้านค้า (Unified Taxonomy Sync)
- **As a:** ร้านค้าและผู้ดูแลระบบ (Merchant & Admin)
- **I want to:** เพิ่มหรือแก้ไขสินค้าโดยเลือกหมวดหมู่ที่ตรงกับแถบแสดงหมวดหมู่บน Dashboard หน้าแรกของร้านค้าแบบ 1:1
- **So that:** สินค้าที่เพิ่มเข้ามาใหม่จะถูกจัดกลุ่มและแสดงผลบน Dashboard หน้าหลักได้ตรงหมวดหมู่อย่างสมบูรณ์ ไม่สับสนชื่อหมวดหมู่
- **Scope หมวดหมู่มาตรฐาน (8 หมวด):**
  1. `ebook`: **E-Books & Manuals**
  2. `figma`: **Figma UI Kits**
  3. `notion`: **Notion Systems**
  4. `code`: **Source Code & SaaS**
  5. `assets`: **3D & Visual Assets**
  6. `creative-ai`: **Creative AI & Prompts**
  7. `multimedia`: **Multimedia & Audio**
  8. `productivity`: **Productivity Packs**

### US-ASSET-01: นำเข้า Brand Icon ประจำเว็บไซต์ (Icon Production.jpg)
- **As a:** เจ้าของแพลตฟอร์ม (Brand Owner)
- **I want to:** ย้ายไฟล์ `Icon Production.jpg` จากโฟลเดอร์ Downloads มาใช้งานเป็น Official Website Icon, App Favicon, PWA Icon และโลโก้แบรนด์หลักของร้านค้า
- **So that:** เว็บไซต์มีอัตลักษณ์ของแบรนด์ (Visual Identity) ที่เป็นเอกภาพ สวยงาม และแสดงโลโก้จริงแทนที่ไอคอนสัญลักษณ์ชั่วคราว
